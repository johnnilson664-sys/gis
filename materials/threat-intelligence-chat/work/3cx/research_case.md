# 3CX 2023 — проверенная фактическая основа нового доклада

Исследование: 14 октября 2026. Читались доступные тексты первоисточников через web_run. Видео не просматривались. Образцы и исходные вредоносные URL не открывались. Это исследовательские заметки для редактора, не текст выступления.

## Вывод для сюжета

Историю можно построить на вопросе «Что мы на самом деле проверили, когда проверили официальную программу?». Реальная техническая основа: Sophos различает чистый основной `3CXDesktopApp.exe`, изменённый `ffmpeg.dll` и `d3dcompiler_47.dll` с добавленной зашифрованной нагрузкой. Следовательно, учебный аналитик, изучивший только основной EXE, ещё не проверил весь исполняемый комплект. Эта последняя фраза — наш учебный вывод из устройства атаки, а не цитата исследователей и не их конкретная ошибочная операция.

Придуманное вводное событие обозначать «Учебная ситуация». Пример: защита остановила привычный телефонный клиент после обновления; коллега возражает «Но он официальный и подписан». Не приписывать этот диалог, журналы, наши проверки или их результаты реальной компании. Внешняя публикация помогает выбрать вопросы, собственные данные должны ответить о конкретном компьютере.

## S1. Sophos: пакет Windows и внутренние проверки

Первичный аналитический материал: https://www.sophos.com/en-us/blog/3cx-dll-sideloading-attack

Текст получен. Первоначальный URL содержит дату 29 марта 2023; сама доступная версия обновлена 6 апреля 2023 в 02:00 UTC. Не читать весь нынешний текст как знание, которым располагали в первый день.

Подтверждает:

- обсуждение возможных ложных срабатываний пользователями началось 22 марта;
- Sophos MDR впервые выявила относящуюся к клиентам злонамеренную активность от 3CXDesktopApp 29 марта;
- ключевые компоненты Windows: чистый `3CXDesktopApp.exe`, `d3dcompiler_47.dll` с добавленной зашифрованной нагрузкой, троянизированный загрузчик `ffmpeg.dll`;
- изменённый `ffmpeg.dll` продолжал выполнять обычные функции программы;
- исследователи встречали вариант `ffmpeg.dll`, подписанный сертификатом 3CX;
- обращения через конкретный путь GitHub связываются с этой кампанией; репозиторий был удалён после огласки;
- код мог отложить дальнейшее сетевое действие: механизм с manifest давал срок 7–28 дней;
- опубликованы запросы по известным доменам/конкретному пути GitHub, библиотекам и хешам, версиям запущенной программы.

Для речи достаточно первых пяти пунктов. Длинное ожидание полезно как необязательное объяснение того, почему проверка одной минуты вокруг установки недостаточна. Таблицы Sophos — примеры конкретного продукта; нельзя объявлять их универсальным SQL для любой SIEM.

## S3. SentinelOne: иконка со спрятанным адресом

https://www.sentinelone.com/blog/smoothoperator-ongoing-campaign-trojanizes-3cx-software-in-software-supply-chain-attack/

Текст получен. Первичная дата: 29 марта 2023. В тексте отмечены обновления 30 марта и расширенный анализ 24 апреля.

Подтверждает:

- всплеск поведенческих детектов наблюдался с 22 марта;
- в Windows-цепочке файлы ICO из специального репозитория содержали дополнительные закодированные сведения;
- после декодирования/расшифровки из них получали C2 URL; затем переходили к следующим действиям и полезной нагрузке;
- анализ описывает сбор конфигурации и сведений о системе, а также истории браузеров;
- macOS-цепочка отличается: троянизированная `libffmpeg.dylib` и жёстко заданный URL вместо получения адреса из иконок;
- первичный исследовательский список позже исправлен: два домена убраны из-за недостоверной связи поставщика passive DNS.

Для новичков: «Обычная картинка могла содержать скрытый адрес следующего шага». Не говорить, что пользователь сам открыл заражённую картинку или что любая иконка на GitHub исполняет вирус. Не путать GitHub целиком с вредоносной инфраструктурой. Исправление индикаторов — хороший короткий пример того, почему нужен источник и версия списка.

## S4. Mandiant: исторические связи, происхождение, атрибуция

https://cloud.google.com/blog/topics/threat-intelligence/3cx-software-supply-chain-compromise

Текст получен. Дата публикации: **20 апреля 2023**.

Подтверждает компрометацию сборочных сред Windows и macOS после проникновения через ранее изменённый установщик X_TRADER. Это цепочка двух атак на поставку ПО. Mandiant обозначает активность как UNC4736 и оценивает связь с северокорейскими операторами; связь с AppleJeus указана с умеренной уверенностью. Это атрибуция исследователей по совокупности анализа, а не вывод из расположения одного IP.

Таблица 1: **2022-12-29 — `pbxphonenetwork[.]com` — UNC4736 — IP `89.45.67.160`**. Таблица 3: **2023-01-09 — `msedgepackageinfo[.]com` — UNC4736 — IP `185.38.151.11`**. Таблица указывает даты исторических DNS-разрешений. Это не текущий DNS и не доказательство роли IP в любой день.

Для демонстрации AbuseIPDB можно взять `89.45.67.160`, явно показав переход от C2-домена Sophos к датированной связи Mandiant. Условный компьютер в нашей истории с ним пока не связан. Совпадение другого домена на этом адресе само по себе не устанавливает общего владельца или одну группировку.

Не смешивать вредоносное ПО внутри разработчика с нагрузкой на компьютерах клиентов. TAXHAUL/COLDCAT/POOLRAT из расследования среды 3CX — не необходимые термины для основного выступления.

## Внутренняя проверка и hunting — редакторский синтез

Это предложение учебной процедуры, не описание выполненного расследования.

Основной вопрос: **Есть ли в выбранной организации устройства с исторически затронутым комплектом 3CX, и есть ли у них наблюдаемые признаки запуска/загрузки соответствующих библиотек и общения с опубликованной инфраструктурой?**

Лучше разделить уровни: (1) наличие нужной версии/установщика/точного хеша DLL; (2) запуск EXE и загрузка DLL, если сенсор пишет модульные события; (3) DNS и соединения — различать DNS-запрос, успешное соединение и URL-запрос; (4) последующая активность, если доступные источники её наблюдают. Наличие файла не равно запуску, запуск не равно успешной загрузке следующей ступени, связь с C2 не доказывает конкретную кражу данных.

Связующие поля: устройство, временная отметка и часовой пояс, полный путь/хеш, пользователь, process GUID либо иной устойчивый ID процесса. Один PID без времени может повторно использоваться. DNS-журнал без процесса не позволяет уверенно сказать, какая программа сделала запрос. При HTTPS сетевой журнал может не содержать путь URL.

Для исторического упражнения фиксировать период **март–апрель 2023** и оговаривать, что данные предоставлены учебной лабораторией. Для настоящего поиска сегодня окно определяется имеющейся ретроспективой, распространением ПО и подтверждённым временем событий, а не автоматически «последние 14 дней» для атаки 2023 года. Не создавать фиктивные журнал/цифру/успешную находку, чтобы закончить историю. Можно завершить формулировкой задания и ожидаемыми колонками результата.

Проверка полноты: количество устройств с инвентаризацией, охват endpoint-сенсорами, наличие событий за выбранное окно, доступность module-load и process-linked network telemetry. Это **вопросы о покрытии**, а не заданные числа. Отрицательный вывод должен говорить «В проверенных источниках и охвате признаки не обнаружены», а не «атаки не было».

В сценарии избегать фантазии о дочернем процессе инфостилера: нагрузка Windows может выполняться в памяти контекста приложения; граф дочерних процессов не является универсальным обязательным следом этой цепочки.

## Что убрать ради младших курсов

- Названия всех malware families, рефлективную загрузку, RC4/XOR, CVE-подпись и assembly.
- Полный список C2, огромный граф атрибуции, число клиентов вендора как число жертв.
- Обещание увидеть theft в одном DNS-запросе или найти всё одной SQL-командой.
- Прямые гиперссылки на C2/иконки/установщики — артефакты печатать defanged, а ссылаться на первоисточники и карточки сервисов.

Достаточная визуальная модель: **Программа → библиотека → скрытый следующий шаг → внешний адрес → вопросы к своим событиям**. На картинке указывать «упрощённая Windows-цепочка по исследованиям 2023», поскольку Mac отличается.
