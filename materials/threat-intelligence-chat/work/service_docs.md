# Проверенные сведения о сервисах для доклада

Проверка официальной документации: 14 октября 2026. Это исследовательские заметки для редактора; текущие оценки конкретных индикаторов здесь не заявляются.

## AbuseIPDB

1. Сервис собирает пользовательские сообщения об активности с IP. CHECK API принимает IPv4/IPv6. `maxAgeInDays` задает окно получения отчетов: по умолчанию 30, допустимо 1–365. `totalReports` — число сообщений в этом окне. `verbose` добавляет отдельные отчеты с датами, категориями и комментариями. `isWhitelisted` не следует использовать как самостоятельное основание действия; возможен `null`. ISP, страна, usage type, связанный домен — обогащение IPinfo, а не доказательство происхождения оператора атаки. Источник: [AbuseIPDB APIv2, CHECK](https://docs.abuseipdb.com/#check-endpoint).

2. `numDistinctUsers` — количество разных пользователей, сообщивших об IP; `lastReportedAt` — время наиболее свежего сообщения. Это разные измерения: множество сообщений может исходить от одного репортера. Для объяснения не называть количество пользователей доказанно независимыми организациями/сетями. Интервал для `totalReports` точно описан в CHECK docs; не утверждать без дополнительной проверки, что `maxAgeInDays` пересчитывает confidence score. Источник: [официальный Bulk Checker Tutorial](https://www.abuseipdb.com/tutorial/bulk-check).

3. `abuseConfidenceScore` — внутренняя оценка уверенности AbuseIPDB на шкале 0–100, основанная на пользовательских сообщениях и их возрасте. Вес стареет, оценка пересчитывается ежедневно; разные репортеры важнее повторов одного. В докладе лучше говорить «оценка сервиса», избегая превращения значения в измеренную вероятность компрометации нашего конкретного события. 0 означает, что сервис не имеет оснований подозревать вредоносность, а не подтверждает безопасность. Источник: [FAQ, вопрос 11](https://www.abuseipdb.com/faq.html).

4. Практическая аналитическая формулировка (вывод из описанной модели): «Нет сообщений в выбранном окне» значит отсутствие видимых сообщений в базе и интервале. Это совместимо с новым адресом, низкой наблюдаемостью, устаревшими сообщениями или еще не заявленной атакой. Даже 100 не доказывает, что именно наше соединение вредоносно; проверяем локальный контекст, время, категорию, текст сообщения. В интерфейсе AbuseIPDB окно графиков может отличаться от переданного в API окна; называем фактически видимое окно.

5. Актуальные ограничения CHECK API Standard — 1 000/сутки; при превышении HTTP 429; остаток и сброс в rate-limit headers. Это не лимит ручного web lookup. Для доклада числа можно убрать: тарифы не нужны новичку, а API не нужен демо. Источник: [AbuseIPDB API limits](https://docs.abuseipdb.com/#api-daily-rate-limits).

## VirusTotal: значения и типы объектов

6. `last_analysis_stats` — счетчики категорий результатов поставщиков. `malicious`: поставщик считает объект вредоносным; `suspicious`: подозрительным; `harmless`: поставщик считает невредоносным; `undetected`: поставщик не дает мнения; `timeout`: анализ не завершился вовремя. Для IP/domain/URL нормализованные категории относятся к URL-scanning services: `undetected` означает отсутствие мнения о сайте, это не `harmless`. Для файлов официальное описание Analysis также формулирует `undetected` как отсутствие мнения AV о файле (в устном объяснении допустимо «этот движок не выдал вредоносный детект»), а не «файл проверен и безопасен». У файлов дополнительно встречаются `confirmed-timeout`, `failure`, `type-unsupported`, то есть ошибки/невозможность анализа. Они не являются отрицательными детектами. `queued` и `in-progress` означают, что результаты еще неполны. Источник: [официальный Analysis object](https://docs.virustotal.com/reference/analyses-object).

7. Аналитический вывод: X/Y — количество срабатываний среди результатов поставщиков, а не процент вероятности атаки и не степень опасности. Не все поставщики одинаковы, не все смогли дать результат. `undetected` не равен `harmless`; нулевое число malicious не дает гарантии безопасности. Одиночное срабатывание может быть ложным, но может требовать расследования. Официальная документация подтверждает возможность ложных срабатываний, в том числе единичных: [VT Intelligence, Identifying potential false positives](https://docs.virustotal.com/docs/virustotal-intelligence-introduction).

8. IP в VT — объект сетевого адреса: ASN/владелец AS, сеть, country, WHOIS, сертификат, URL-scanner verdicts, связи с файлами/URL. `last_analysis_date` — время последнего анализа именно IP; `last_modification_date` — изменение любых сведений об объекте; `whois_date` — обновление WHOIS; `last_https_certificate_date` — когда сертификат получен VT. Эти даты не взаимозаменяемы и не доказывают время атаки. Community reputation/votes — отдельный сигнал, не счетчик антивирусных детектов. Источник: [IP object](https://docs.virustotal.com/reference/ip-object).

9. Domain/FQDN тоже объект инфраструктуры; verdicts происходят от URL-scanning services. Есть последние DNS-записи и дата их получения, creation_date из WHOIS, даты сертификата/анализа. DNS относится к домену и времени наблюдения; он не приписывает всем размещенным на IP сайтам один статус. Совпадение IP/ASN — повод проверить отношения и время, а не атрибуция. Источник: [Domain object](https://docs.virustotal.com/reference/domains-object).

10. Файл — объект конкретных байтов: его ID в VT — SHA-256. Можно получить существующий отчет по MD5/SHA-1/SHA-256. `last_analysis_date` отличается от `first_submission_date`, `last_submission_date` и даты последнего изменения объекта. У файла есть AV verdicts и отдельные sandbox verdicts; sandbox confidence не равен числу AV-срабатываний. Источники: [File object](https://docs.virustotal.com/reference/files), [Get file report](https://docs.virustotal.com/reference/file-info).

11. URL — отдельный объект; URL, domain и IP — разные уровни. Последний URL-отчет может содержать verdicts и сведения о HTTP-ответе/редиректах. Проверка домена не покрывает каждую страницу/путь/параметры URL. `last_analysis_date` описывает последний анализ URL. Источник: [URL object](https://docs.virustotal.com/reference/url-object).

12. Статус инфраструктуры оцениваем отдельно от репутации: доступны ли свежие DNS/HTTP/сертификат/наблюдения связей, когда они зафиксированы, совпадает ли адрес с периодом инцидента. «Последний анализ» — дата анализа сервисом, не обязательно последняя активность злоумышленника; недоступный сейчас C2 мог быть активен тогда. Это аналитическое применение дат и отношений, не универсальный отдельный VT verdict «активный C2».

## Lookup, перескан и конфиденциальность — важная свежая поправка

13. GET file/URL report возвращает имеющийся объект; POST analyse явно запрашивает новый анализ и возвращает analysis ID. Файл можно пересканировать без повторной загрузки его байтов. Для IP перескан обновляет verdicts, WHOIS, SSL и другие сведения. Источники: [Get URL report](https://docs.virustotal.com/reference/url-info), [File re-analyze](https://docs.virustotal.com/reference/files-analyse), [URL re-analyze](https://docs.virustotal.com/reference/urls-analyse), [IP re-scan](https://docs.virustotal.com/reference/rescan-ip).

14. НЕЛЬЗЯ обещать, что произвольный VT lookup всегда пассивен/конфиденциален. Текущая официальная Searching документация (обновлена ~20 дней назад) предупреждает: IoC, переданный ИЛИ запрошенный через web, будет анализироваться и попадет в dataset, доступный community. Не запрашивать индикаторы с чувствительной/конфиденциальной/персональной информацией. Ниже та же страница поясняет: готовый отчет по hash/URL можно показать без повторной отправки файла/URL. Согласованное объяснение: чтение уже существующего отчета и явный Reanalyze — разные действия, но новый запрос в стандартный сервис не является гарантией отсутствия обработки/раскрытия. Источник: [Searching](https://docs.virustotal.com/docs/searching).

15. Аналогичное предупреждение есть для API. Обычная публичная загрузка не подходит для внутренних документов, клиентских файлов, токенов, приватных ссылок, login/reset URLs. URL может содержать секрет в пути или query string; хеш не содержит байты файла, но новый запрос индикатора также передает данные внешнему сервису. Источник: [Upload file, IoC scanning and dataset inclusion](https://docs.virustotal.com/reference/files-scan). Не цитировать historic ToS как актуальные условия: docs terms/privacy теперь перенаправляют на Google Cloud, а старые страницы явно historic.

16. Private Scanning — отдельная платная функция и отдельная форма/endpoints. Файлы/URL и отчеты ограничены организацией и сроком хранения; нет обычных AV/url-scan partner verdicts. Наличие premium/private API не означает, что стандартная загрузка стала private. Источник: [Private Scanning](https://docs.virustotal.com/docs/private-scanning).

17. Public API по проверенной текущей документации: 500 запросов/сутки и 4/минуту; ограничено использование в commercial products/services и business workflows без вклада новых файлов; не обходить лимиты несколькими аккаунтами. Для ручного 1–2-минутного демо API не нужен. Источник: [Public vs Premium API](https://docs.virustotal.com/reference/public-vs-premium-api).

## Необязательный urlscan.io

18. Public виден на главной и в публичном поиске. Unlisted отсутствует в публичной выдаче, но доступен проверенным исследователям/компаниям через urlscan Pro; это не private. Private виден владельцу и тем, кому передан scan ID, с ограниченным сроком хранения. Сканирование сайта предполагает посещение его сервисом; для данного доклада предлагается только чтение уже готового публичного отчета. Источник: [Scan Visibility Levels](https://docs.urlscan.io/pages/visibility).

## Конкретное безопасное демо (1–2 минуты)

Предпочтение: заранее проверенная ссылка на существующий отчет SHA-256 из выбранного официального публичного кейса; не заходить на подозрительный URL/IP, не скачивать файл, не жать Upload/Scan/Reanalyze. Поскольку отчет динамический, перед выступлением сохранить скриншот с датой и использовать его при недоступности сервиса. Не выдумывать X/Y; на живом отчете читать фактически видимое значение и время.

Запасной известный публичный объект: отчет тестового EICAR по SHA-256 `275a021bbfb6489e54d471899f7db9d1663fc695ec2fe2a2c4538aabf651fd0f` — [готовая VT ссылка](https://www.virustotal.com/gui/file/275a021bbfb6489e54d471899f7db9d1663fc695ec2fe2a2c4538aabf651fd0f/detection). Хеш используется в [официальной VT документации YARA metadata](https://docs.virustotal.com/docs/writing-yara-rules-for-livehunt). EICAR — безвредный стандартный тест реакции антивируса, а не образец реального вредоносного ПО: [EICAR](https://www.eicar.org/download-anti-malware-testfile/). Сам файл не загружать, не создавать и не скачивать. Важно произнести: положительные детекты здесь ожидаемы из-за тестовой сигнатуры; пример показывает, почему нужен контекст. Это не замена основному кейсу.

Пример хода:

- 0:00–0:20: показать, что открыта карточка файла по хешу, назвать источник индикатора и публичный контекст.
- 0:20–0:45: показать дату последнего анализа и фактически видимое количество malicious; объяснить, что число — счетчик результатов.
- 0:45–1:10: показать две строки verdicts, различить undetected и harmless/timeout; не объяснять отсутствие детектов как «разрешено».
- 1:10–1:40: показать Details/Relations у основного кейса или ограничиться Details для EICAR; сформулировать вывод «репутация + время + отношения + локальное событие», без скачивания артефактов и новых сканов.

Текущие scores и числа сообщений AbuseIPDB намеренно не фиксируем; динамические значения могут измениться. Количество детектов EICAR инструментом не получено (VT требует JavaScript).

Альтернатива для IP без привязки к Luna Moth: `118.25.6.39` из официального исторического примера CHECK API, [готовая AbuseIPDB карточка](https://www.abuseipdb.com/check/118.25.6.39). Строго назвать его «независимый исторический учебный пример из документации, сообщение от декабря 2018», а не «IP Luna Moth» или «активный сейчас атакующий адрес». Цифры в JSON документации — числа исторического примера, не текущий результат. Если живую карточку проверить заранее невозможно, использовать сам официальный JSON с явно указанной исторической датой и таблицу значений полей. Основной кейс не получает новый выдуманный индикатор.
