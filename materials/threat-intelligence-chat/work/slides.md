## 5. Бриф 14 слайдов

Слайды не являются отдельным рассказом: они поддерживают речь из раздела 4. Указанные комментарии — акцент, а не дополнительный текст поверх хронометража. На схемах учебные части подписаны «Учебная ситуация», реальные — названием исследователя и годом. На титуле добавить [Название компании]; логотипы сервисов не использовать как знак партнерства.

### 1. Программа настоящая. А поддержка? • 00:00–01:20

**Мысль:** даже простое обращение содержит неопределенность. **Экран:** три короткие реплики сотрудника: письмо о подписке → сам позвонил по номеру из счета → запустил удаленную поддержку. Внешний адрес — отдельная карточка без значения и оценки; подпись «Учебная ситуация». **Комментарий:** мы знаем сообщение сотрудника, но не знаем действия оператора. Первый вопрос залу — с чего начать. **Переход:** «Что именно мы сейчас собираемся искать?»

### 2. Адрес — наблюдение. IoC — наблюдение с контекстом • 01:20–03:10

**Мысль:** объект не доказывает компрометацию. **Экран:** три группы: сеть — IP/домен/URL; файл — SHA-256; контекст — письмо/номер/сеанс. Под ними пример: разрешенная и неразрешенная сессии одного инструмента. **Комментарий:** не все имена файлов и адреса автоматически становятся IoC. **Переход:** «Чем внешний поиск поможет работе аналитика?»

### 3. Внешние данные меняют следующий вопрос • 03:10–04:30

**Мысль:** репутация, обогащение, анализ TI, расследование и hunting выполняют разные задачи. **Экран:** короткая цепочка: оценки → сведения → объяснение → проверка события → поиск гипотезы в истории. **Комментарий:** определять через действие, без отдельной лекции о терминах. **Переход:** «Перед поисковой строкой запишем вопрос».

### 4. Один объект — один проверяемый вопрос • 04:30–06:10

**Мысль:** источник выбирается под вопрос. **Экран:** IP → история сообщений; SHA-256 → точный файл; домен/URL → объект нужного уровня; локальные журналы → процесс и действия. **Комментарий:** SHA-256 — отпечаток байтов, URL включает конкретный путь, домен его не заменяет. **Переход:** «Начнем с истории адреса».

### 5. AbuseIPDB: что сообщали об адресе? • 06:10–08:20

**Мысль:** важны содержание, период и происхождение сообщений. **Экран:** схема полей «период / дата / категория / репортеры / оценка сервиса», без нарисованных результатов. **Комментарий:** количество сообщений не равно количеству атак; confidence не является вероятностью нашего инцидента. [R6–R7] **Переход:** «Теперь проверим другой объект и другой тип свидетельства».

### 6. VirusTotal: что известно именно об этом объекте? • 08:20–10:40

**Мысль:** тип объекта, дата, вердикты и связи важнее одного счетчика. **Экран:** четыре карточки IP / domain / URL / file; определения malicious, undetected, harmless; строка «доля детектов ≠ вероятность». **Комментарий:** IP не файл, URL не весь домен. Второй вопрос залу — можно ли закрыть событие при отсутствии детектов. [R8–R10, R12] **Переход:** «Прежде чем вводить значение, проверим, что раскрывает запрос».

### 7. Готовый отчет, запрос, загрузка • 10:40–12:10

**Мысль:** чтение готового отчета и передача содержимого — разные действия, но внешний запрос тоже раскрывает данные. **Экран:** hash/report; Upload; Reanalyze; короткая выдержка смысла актуального предупреждения VT, своими словами. **Комментарий:** приватные файлы, ссылки и токены — в разрешенном контуре. Не обещать приватность произвольного lookup. [R11] **Переход:** «Для демонстрации возьмем уже опубликованный исторический объект».

### 8. Два источника — два вопроса • 12:10–13:50

**Мысль:** отчет надо читать как свидетельство с ограничениями. **Экран:** подготовленные карточки/скриншоты либо таблица Sygnia; большая подпись «Исторический объект из отчета 2022; к учебному хосту не привязан». **Комментарий:** сценарий раздела 6; не обещать видимые поля и не подставлять scores. **Переход:** «Почему этот реальный кейс меняет направление проверки?»

### 9. Luna Moth: привычные инструменты в цепочке обмана • 13:50–15:40

**Мысль:** назначение действий раскрывается через последовательность. **Экран:** счет → звонок → удаленная поддержка → дальнейшие действия → передача данных; подписи Sygnia / Unit 42, 2022. **Комментарий:** это опубликованные расследования исследователей; описанная кампания не определяет все действия группы. [R1–R2] **Переход:** «Какие связи можно взять из публикации и где остановиться?»

### 10. Нашли связь — проверяем время и основание • 15:40–17:10

**Мысль:** связь помогает проверке, но не устанавливает автора атаки. **Экран:** домен `maaays[.]xyz` ↔ IP `192[.]236[.]194[.]2`, пунктир к надписи «роль в отчете 2022». Рядом три проверки: источник / время / характер связи. **Комментарий:** таблица исследователя не является текущим DNS; общий хостинг не доказывает общий контроль. [R1, R9] **Переход:** «Теперь возвращаемся к учебному сотруднику».

### 11. Что произошло у нас? • 17:10–19:30

**Мысль:** внутренние источники отвечают на вопрос о действиях. **Экран:** почта и человек → устройство/процесс → сессия поддержки → сеть/передача; под каждым «что можем подтвердить». Результаты не рисовать. **Комментарий:** объяснить EDR и DNS одним предложением; факт соединения не равен краже. **Переход:** «Как записать вывод, когда часть данных еще отсутствует?»

### 12. Вывод, который можно проверить • 19:30–20:50

**Мысль:** факт, гипотеза и следующий шаг записываются отдельно. **Экран:** событие / внешнее свидетельство / внутренняя проверка / пробел / действие. Пример с пометкой «Учебная запись; проверка не выполнена». **Комментарий:** не объявлять учебное событие атакой. **Переход:** «Из этого вопроса можно сделать поиск в истории».

### 13. Hunting начинается с гипотезы • 20:50–23:30

**Мысль:** ищем возможное неразрешенное поведение в доступном охвате. **Экран:** гипотеза «удаленная поддержка → передача файлов»; окно «14 дней — условие упражнения»; проверить согласование и полноту данных. **Комментарий:** третий вопрос залу — что значит отсутствие находок. Показать подтверждение, альтернативное объяснение и ограничения отрицательного результата. **Переход:** «Что мы теперь сделаем с исходным обращением?»

### 14. Объект → вопрос → источник → проверка → действие • 23:30–25:00

**Мысль:** слушатель уносит порядок работы. **Экран:** та же схема, что в начале, и краткий шаблон заметки. **Комментарий:** вернуться к сотруднику; цель — обоснованный следующий шаг, имя группировки не требуется. **Переход:** завершить речь, затем открыть отдельное время на вопросы.
